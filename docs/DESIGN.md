# gw-worktime — 아마란스 근무시간 크롬 확장 설계

작성일: 2026-09-01

## 배경

회사 근태 시스템이 flex에서 더존 아마란스 그룹웨어(`gw.goorm.io`)로 바뀌었다.
기존에 쓰던 `unofficial-flex-extension`(v3.4.7)처럼, 그룹웨어에 들어가지 않고
크롬 확장 팝업에서 이번 달 근무시간 현황을 확인하는 것이 목적이다.

기존 확장의 근무 탭 기능만 이식한다. 휴가 잔여일수 조회(휴가 탭)는 범위 밖이다.
출퇴근 찍기 같은 쓰기 동작도 넣지 않는다 — 오작동 시 실제 근태 기록이 틀어지기 때문이다.

## 인증 방식

그룹웨어 API는 쿠키만으로는 호출할 수 없고 HMAC 서명 헤더를 요구한다.
서명 알고리즘은 프론트엔드 번들(`/static/js/main.*.js`)에서 확인했고, 재현하여 200 응답을 검증했다.

```
wehago-sign = Base64( HmacSHA256( oAuthToken + transactionId + timestamp + pathname, signKey ) )
```

| 요소 | 출처 |
|---|---|
| `oAuthToken` | 쿠키 `oAuthToken` (형식: `<그룹 코드>\|<empSeq>\|<랜덤>`) |
| `signKey` | 쿠키 `signKey` (44자) |
| `transactionId` | 요청마다 새로 만드는 랜덤 hex 32자 |
| `timestamp` | 초 단위 유닉스 시각 (문자열) |
| `pathname` | 요청 URL의 path. 쿼리스트링 제외 |

필수 요청 헤더:

```
authorization:  Bearer <oAuthToken>
timestamp:      <timestamp>
transaction-id: <transactionId>
wehago-sign:    <signature>
access-domain:  https://gw.goorm.io
content-type:   application/json
menu-code:      HPD0220        // 근태 관련 API에만
```

확장은 `chrome.cookies.get({url:'https://gw.goorm.io', name:...})`으로 두 쿠키를 읽는다.
`credentials`는 쓰지 않는다 — 헤더 인증만으로 통과하며, 쿠키를 실어 보내면
`허용된 쿠키 인증 URL이 아닙니다`(601) 오류가 난다.

서명이 없으면 401 `인증 요청 시, Wehago-sign 값을 넣어야 합니다`(136)를 받는다.

## 사용하는 API

### 1. 오늘 출퇴근 — `POST /human/common/judgeTimeManagement/getTodayComeLeaveInfo`

```json
요청: {"empCd":"<사번>","coCd":"1000","workDt":"20260901"}
응답: {"resultData":{"comeTm":"202609011027","leaveTm":"","holidayYn":"N"}}
```

`comeTm`/`leaveTm`은 `yyyyMMddHHmm`. 미등록이면 빈 문자열.

### 2. 일자별 근무 기록 — `POST /personal/hpd0210/getWorkTimeList`

```json
요청: {"coCd":"1000","empCd":"<사번>","atDtList":["20260901","20260902", ...]}
헤더: menu-code: HPD0210
```

개인 근무시간 조회(HPD0210) 화면이 쓰는 경로다.

**왜 이 경로인가**: 인사 관리 모듈의 `/human/hrd0410/selectTab2` 로도 같은 값을 얻을 수 있고
실제로 한 달치를 두 경로로 조회해 인정 근무시간과 소정 시간이 완전히 일치하는 것을 확인했다.
하지만 그쪽은 `admin: true` 와 `menu-code: HPD0220`(근무시간현황)을 요구하는 관리 메뉴라
**권한이 없는 사람에게는 동작하지 않는다.** 개인 모듈을 쓰면 누구나 자기 기록을 볼 수 있다.

응답은 날짜별 행 배열. 쓰는 필드:

| 필드 | 의미 |
|---|---|
| `atDt` | 날짜 `yyyyMMdd` |
| `comeTm` / `leaveTm` | 출근/퇴근 시각 `HHmm`. **값이 없으면 `"----"`** |
| `basicworkTm` | **인정 근무시간(분)**. 휴게·자리비움이 차감되고 반차 등이 반영된 값 |
| `selfCommuteStandardWorkTm` | **그날의 소정 근로시간(분)**. 평일 480, 휴일 0 |
| `attresultNm` | `정상근무` / `출근` / `휴일`. 값이 없으면 `"-"` |
| `atNm` | 휴가명 (`오전반차` 등) |
| `exceptworkTm` | 그날 차감된 휴게 시간(분) |
| `workNm` | 근무 유형 (`자율출퇴근`) |

**빈 값 표기에 주의**: 시각은 빈 문자열이 아니라 `"----"`, 결과명은 `"-"` 로 온다.
그대로 파싱하면 `NaN` 이 화면에 새어 나온다. `lib/api.js` 에서 빈 문자열로 정규화한다.

**중요한 제약**: 요청한 날짜는 모두 행으로 돌아오지만, **아직 오지 않은 날은 빈 껍데기다**
(소정·인정 모두 0). 당일 행도 퇴근을 찍기 전에는 채워지지 않는다.
따라서 이번 달 남은 근무일은 공휴일 API와 요일로 따로 계산해야 한다(아래 참조).

### 3. 월 합계 — `POST /personal/hpd0220/0hr00001`

```json
요청: {"atDtFrom":"20260801","atDtTo":"20260831"}
응답: {"resultData":{"basicworkTm":"<분>","exceptworkTm":"<분>","nightworkTm":"<분>", ...}}
```

2번을 합산해도 같은 값이 나오므로 **검증용 보조 수단**으로만 쓴다. 필수는 아니다.

### 4. 휴가 일정 — `POST /schres/sc111A03`

```json
요청: {"companyInfo":{"compSeq":"1000","groupSeq":"<그룹 코드>","deptSeq":"","emailAddr":"","emailDomain":""},
       "startDate":"20260901","endDate":"20260930","mySchYn":"N",
       "calList":[],"tcalList":[],"acalList":["1"],
       "searchEmpSeq":"","excelYn":null,"abUID":"","sortDate":"Y","langCode":"kr"}
```

근태캘린더(`acalList: ["1"]`)를 조회한다. 근무 기록과 달리 **앞으로 예정된 휴가도** 들어 있다.

주의할 점:

- **부서 전체의 일정이 내려온다.** `searchEmpSeq` 를 채워도 서버가 걸러 주지 않으므로
  `partSeq === 본인 empSeq` 로 클라이언트에서 직접 필터해야 한다.
- `companyInfo.groupSeq` 와 본인 `empSeq` 는 **`oAuthToken` 쿠키에서 뽑을 수 있다.**
  토큰이 `groupSeq|empSeq|랜덤` 형식이다. `deptSeq` 와 이메일은 빈 문자열이어도 통과한다.
- 응답의 `startDate`/`endDate` 는 `yyyyMMddHHmm`. 여러 날짜에 걸친 연차는 한 건으로 온다.

휴가는 **표시 전용**이다. 계산에는 넣지 않는다 — 아마란스가 반차·연차를 이미
`basicworkTm`(인정 근무시간)에 반영해서 내려주기 때문에, 따로 더하면 이중 계산이 된다.

### 5. 공휴일 — `POST /gw/APIHandler/gw114A14`

```json
요청: {"startDate":"20260901","endDate":"20260930","compSeq":"1000"}
응답: {"resultData":[{"comp_seq":"0","h_day":"20260924","title":"추석연휴"},
                     {"comp_seq":"0","h_day":"20261005","title":"대체공휴일(개천절)"}]}
```

`comp_seq`가 `"0"`이면 법정공휴일, 회사 코드면 회사 지정 휴일이다. 둘 다 근무일에서 제외한다.
이 API 덕분에 공휴일 테이블을 내장하거나 외부 API를 붙일 필요가 없다.

## 사번(empCd) 확보

`empCd`(사번)와 `coCd`(`1000`)는 어느 API 응답에도 없고
그룹웨어 페이지의 `sessionStorage.userInfo` 안에만 있다:

- `erpUserInfo.userCode` → `empCd`
- `ucUserInfo.erpEmpSeq` → 사원 seq (보조)

확장은 `sessionStorage`에 직접 접근할 수 없으므로, content script를 `gw.goorm.io`에 주입해
값을 읽어 `chrome.storage.local`에 한 번 저장한다. 이후에는 그룹웨어에 들어가지 않아도 된다.

값이 아직 없으면 팝업에 "그룹웨어에 한 번 접속해 주세요 + 열기 버튼"을 띄운다.

## 계산 규칙

```
휴게시간 = 서버 exceptworkTm(그날 실제 차감 휴게 분)이 있으면 그 값.
            없으면 매일 12:00 ~ 13:00 60분 폴백.
            빈 껍데기 행의 0 은 "아직 모름"이라 폴백을 쓰고,
            출근·소정이 채워진 날의 0 은 휴게 면제로 본다.

기준선: 값이 채워져 돌아온 날짜를 "기록된 날", 이번 달의 나머지를 "남은 날"로 본다.
        두 집합은 겹치지 않으므로 어느 쪽에도 중복 계산이 생기지 않는다.
        오늘은 퇴근을 찍기 전까지 "남은 날"에 속하고, 퇴근을 찍으면 "기록된 날"로 옮겨간다.

남은 근무일 = 남은 날 중 토·일이 아니고 공휴일도 아닌 날의 수   // 퇴근 전이면 오늘 포함

월 소정   = Σ(기록된 날의 workGroupStandardWorkTm) + (남은 근무일 × 480분)

누적      = Σ(기록된 날의 basicworkTm)              // 서버 확정값
          + 오늘 진행분                             // 오늘이 아직 남은 날일 때만 (추정값)

오늘 진행분 = (지금 − 출근시각) − 휴게 차감
            // 휴게 차감: 기본 12~13시와 겹친 분. exceptworkTm 이 60보다 짧으면 그 총량을 넘지 않고,
            // 길면 13시 이후에 초과분을 더 뺀다. 출근 전이면 0.
            // 퇴근을 찍으면 이 항은 사라지고 서버의 basicworkTm 이 대신 들어간다

이번 달 근무일 = 이번 달 전체 날짜 중 토·일이 아니고 공휴일도 아닌 날
                // 화면에는 "남은 2일 / 전체 20일" 형태로 함께 보여준다

오늘 남은 시간 = 하루 소정(기본 480분) − 오늘 일한 시간
                // 월 배분과 무관하게 "오늘 하루만 보면 얼마 남았나"에 답하는 값

초과·부족 누적 = Σ(지난 날의 basicworkTm − 그 날의 소정)
                // 양수면 적립, 음수면 빚. 아래 오늘 권장에 이미 반영되어 있다

부족한 시간 = 월 소정 − 누적                        // 화면에 표시하는 값. 오늘 진행분이 반영된다

오늘 권장   = (월 소정 − Σ기록된 날의 basicworkTm) ÷ 남은 근무일
            // 분모·분자 모두 오늘 진행분을 빼고 잡는다.
            // 진행분을 넣으면 시간이 흐를수록 목표가 줄어들어 퇴근 시각이 계속 앞당겨진다.
            // 남은 근무일이 0이면 표시하지 않는다.

퇴근 가능   = 출근시각 + 오늘 권장 + 그 구간의 휴게 차감
            // 휴게 전에 목표를 채우면 더해지지 않는다. exceptworkTm 이 있으면 그 총량만큼 밀린다
```

### 검증

한 달치 실제 응답으로 계산식을 맞춰 보았다.

- 2026년 8월 평일 20일 → `Σ workGroupStandardWorkTm` = 9600분 = **160시간**.
  광복절이 토요일이라 생긴 8/17 대체휴일도 정확히 0으로 잡힌다.
- 하루 예: 09:23 출근 ~ 18:16 퇴근 = 533분, 휴게 53분 차감 → 인정 480분 ✅
- **퇴근을 찍지 않은 날은 인정 근무시간이 0으로 처리된다.** 월 합계가 소정보다
  크게 모자라 보이는 가장 흔한 원인이므로, 화면에 경고로 노출한다.

상태 표시는 세 가지: `출근 전` / `근무중 · N시간 M분째` / `퇴근 · 오늘 N시간 M분`.

큰 숫자는 **퇴근 가능 시각 ⇄ 이번 달 부족한 시간**을 오간다. 클릭 또는 `Alt+Shift+T`.
선택한 쪽은 저장되어 다음에 열 때도 유지된다.

### [설정] 탭

하단 "설정"으로 들어간다. 적용된 근무규칙(규칙 이름, 기본 근무시간)을 보여주고,
하루 근무시간을 직접 바꿀 수 있다. 기본값은 그룹웨어가 주는 8시간이다.
단축키 목록도 여기 적어 둔다.

### [기록] 탭

상단에 `‹ 2026년 9월 ›` 월 이동. 아직 오지 않은 달은 볼 것이 없으므로 다음 달 버튼은 잠근다.
한 번 불러온 달은 팝업이 열려 있는 동안 다시 부르지 않는다.

**달력** — 일요일 시작 7열. 칸마다 날짜와 그날 인정 근무시간(`8:06`)을 넣는다.

| 상태 | 표시 |
|---|---|
| 근무한 날 | 블루 농도 4단계 (소정 대비 60% / 95% / 110% 로 나눈다) |
| 종일 휴가 | 오렌지로 칸을 꽉 채우고 `연차` |
| 반차 | 쉬는 시간대 쪽 절반만 채운다 — 오전이면 위, 오후면 아래 |
| 퇴근 미등록 | Red 050 + `미등록` |
| 일요일·공휴일 | 붉은 날짜 + 공휴일 이름 |
| 오늘 | 블루 테두리 |

칸을 누르면 아래에 그날 상세(출근→퇴근, 인정 근무시간, 휴가명)가 열린다.

**요약** — 달력 아래 세 줄. 근무일 수와 **그 근거**, 인정 근무 합계, 퇴근 미등록 목록.
근거를 함께 적는 이유는, 숫자만 보면 "9월 평일은 22일 아닌가?" 라는 의문이 남기 때문이다.
`근무일 20일 — 평일 22일 − 공휴일 2일` 처럼 보여준다.

**휴가** — 그 달의 본인 휴가를 날짜순으로. 여러 날에 걸친 연차는 `9/21 (월) ~ 9/23` 형태로 묶는다.

### 오류 상태

| 상황 | 화면 |
|---|---|
| 쿠키 없음 / 401 | "그룹웨어 로그인이 필요해요" + 로그인 열기 버튼 |

## 디자인

구름 디자인 시스템(Vapor) 토큰을 쓴다. 중립 회색 화면에 블루 강조 하나,
카드는 1px 테두리 + 12px 라운드, 색면 헤더 대신 상태 배지, 밑줄 탭.
글꼴은 Pretendard Variable 을 `fonts/` 에 내장하고 `unicode-range` 로 나눠
필요한 조각만 받도록 했다.

색이 뜻하는 것은 네 가지뿐이다 — 블루 농도(근무시간), 오렌지(휴가),
Red 050(퇴근 미등록), 붉은 날짜(휴일). 그 밖에는 색을 쓰지 않는다.

## 구조

```
manifest.json      MV3. host_permissions: https://gw.goorm.io/*
                   permissions: cookies, storage
background.js      쿠키 읽기 → 서명 → API 호출 → 계산 → storage 캐시
content.js         gw.goorm.io 에서 sessionStorage.userInfo 읽어 저장 (1회)
popup.html
popup.js           두 탭 렌더, background에 갱신 요청
popup.css
icons/
```

빌드 도구를 쓰지 않는다. 화면 두 개짜리 확장에 번들러는 과하고,
폴더를 그대로 `chrome://extensions`에서 "압축해제된 확장 프로그램 로드"로 올리면 된다.

모듈 경계:

- `background.js`는 **인증·호출·계산**만 한다. DOM을 모른다.
- `popup.js`는 **표시**만 한다. 계산하지 않고, 서명도 모른다.
- 둘 사이는 `chrome.runtime.sendMessage`로 계산 완료된 평평한 객체 하나를 주고받는다.

계산 로직(`월 소정`, `남은 근무일`, `오늘 진행분`)은 순수 함수로 분리해
날짜·기록 배열을 넣으면 숫자가 나오도록 한다. 그래야 테스트가 가능하다.

## 캐시와 갱신

- 팝업을 열 때마다 갱신한다. 응답은 `chrome.storage.local`에 저장한다.
- 오늘 데이터(1번 API)만 매번 부르고, 일자별 기록(2번)과 공휴일(4번)은 30분 캐시한다.
- 오늘 진행분은 팝업이 열려 있는 동안 1분마다 화면에서 다시 계산한다(API 호출 없음).

## 범위 밖

- 출퇴근 찍기 등 모든 쓰기 동작
- 휴가 잔여일수 조회
- 확장 아이콘 배지, 알림
- 여러 사용자 / 팀원 조회

## 알려진 한계

- **비공식 확장**이다. 그룹웨어가 서명 방식이나 API 응답 형식을 바꾸면 동작하지 않는다.
- 그룹웨어 세션이 만료되면 확장도 401을 받는다. 확장이 로그인을 대신할 수는 없고,
  사용자가 그룹웨어에 다시 로그인해야 한다.
- 퇴근 전 표시되는 오늘 근무시간은 **추정치**다. 실제 인정 시간은 퇴근 등록 후 서버가 확정한다.
- 반차가 있는 날의 진행분 추정은 부정확할 수 있다. 확정값이 들어오면 자동으로 교정된다.
